# Razer Naga Trinity HID Linux Kernel Driver

This is a HID driver made for controlling the LEDs ona Razer Naga Trinity mouse.
It supports setting the individual zones separately.

## Explanation of directories

- driver - this is the kernel driver code
- python - this is code that I used to reverse engineer the Razer USB protocol
- gui - a simple GUI app that is meant to show off the functionality of the driver

## Useful commands

### Recompile the driver

Execute in the driver directory

```bash
make clean && bear -- make

```

#### Bear

The `bear` command is optional but it generates the file `compile_commands.json`,
so that clang knows whats going on in the project.
This way you can move around the code and jump to the kernel headers.

### Insert/Remove the kernel module

Execute in the driver directory

Remove the module:

```bash
sudo rmmod razernagatrinity
```

Insert the module:

```bash
sudo insmod razernagatrinity.ko
```

### Turn on the GUI app

Execute in the gui directory

```bash
sudo venv/bin/python main.py
```

Turns on the GUI. Before running it,
you of course need to install the `requirements.txt`, preferably in a venv.

You don't need to be in the venv to execute this command.

I know that using `sudo` to open the gui is not ideal, but I found this is
simpler than creating a `udev` rule to set the permissions.

## Configuring clangd for a nice NeoVim experience

Copy the file `clangd_config/config.yaml` to `~/.config/clangd/config.yaml`
Remember to replace the kernel name from `6.17.12-300.fc43.x86_64` to
the output of `uname -r` command.
This way you will be able to jump around the kernel headers more easily.

You might need to download some kernel development headers on your distro.

In my file there is a mismatch between the architectures (x86_64 and arm64)
as I was developing this on both, but found that it didn't matter in practice,
if you just want to read some kernel headers,
as this is not used for compilation, only for hints.

Next copy the `clangd_config/.clangd` into your driver directory.
This disables some flags that are in the `compile_commands.json` file
generated by the [`bear`](#bear) command.
Because compiling the driver by default uses gcc,
not all the flags that are in the `compile_commands.json`
file are supported by clangd.
These flags lead to nonexistent errors that clutter up the editor.
